# Vibe coding is fine for throwaway projects

In February 2025 Karpathy named a style of work: vibe coding. You give in to the vibes. You talk to the editor by voice, accept every change, and never read the diffs. You paste error messages back with no comment. If a bug will not go away, you work around it. He says this is fine for throwaway weekend projects. The code grows past what you understand, and you stop caring that it exists. The idea is a label for a real way of working, with a clear limit on where it is safe.

## In his words

> "forget that the code even exists"
> — Andrej Karpathy, 2025-02-02

## Apply

- Use vibe mode for disposable prototypes, demos and one-off scripts only.
- For code you keep, read the diffs and run tests. See [a rhythm for code you care about](2025-04-24-ai-assisted-coding-rhythm.md).
- Paste raw error output into the agent instead of describing it. This is the cheapest loop for a throwaway project.
- Decide before you start whether the project is throwaway. Write that in the first prompt.
