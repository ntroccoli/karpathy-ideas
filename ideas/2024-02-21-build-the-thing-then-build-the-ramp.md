# Build the thing, then build the ramp

Karpathy says his micrograd project stagnated until he made a from-scratch video. The same code then got about a hundred times more engagement. Technical people assume code and a README explain themselves. They do not. Accessibility leaves ten to a hundred times of reach on the table. His rule has two steps: build the thing, then build the ramp that lets others climb onto it.

## In his words

> "Step 1 build the thing. Step 2 build the ramp."
> — Andrej Karpathy, 2024-02-21

## Apply

- After a project works, ask the agent for a walkthrough: a guided tour of the code, an HTML explainer or a script for a video.
- Write the ramp for your future self too: why the design is this way, and how to run it.
- Test the ramp on someone new to the code.
